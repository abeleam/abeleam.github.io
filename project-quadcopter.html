Overview

Built a custom quadcopter from scratch as part of a 3-person team, achieving stable hover under bench power supply. The project integrated motor control, sensor fusion, and wireless input in a compact embedded system. I was responsible for flight control architecture, ESC calibration, and motor driver programming.

System Architecture

The quadcopter uses an ATmega328PB microcontroller as the central flight computer, running a real-time control loop at approximately 200 Hz. The system integrates:

  • Motor Control: Four brushless motors driven by ESC (Electronic Speed Controllers) via PWM on pins 5, 6, 9, and 10
  • Sensor Fusion: I2C-based IMU (6-axis accelerometer + gyroscope) providing real-time attitude estimation
  • Stabilization: PID control loops for pitch, roll, and yaw to maintain stable flight
  • User Input: Bluetooth UART receiver decoding Xbox controller commands at 9600 baud
My Contributions

Motor Control & PWM

Programmed PWM output on the ATmega328PB to drive the four brushless motors across the full throttle range (1000–2000 microsecond pulse widths). Debugged motor spin direction and calibration issues by running each motor individually and verifying 1:1 correspondence with throttle input. Handled edge cases like rapid throttle changes and ESC initialization sequences.

ESC Calibration Pipeline

Developed the calibration routine to sync all four ESCs to identical throttle responses. This involved sending max/min throttle signals in a specific sequence, then validating that each motor responds linearly to control input. Misaligned ESCs caused yaw drift during hover, so this was critical for stability.

Mechanical Design

Designed the drone's X-configuration chassis in Fusion 360 and 3D printed it with reinforced motor mounts. The design balanced structural rigidity with minimal weight, and included cable routing channels to keep wiring organized inside the frame.

Wireless Input
Bluetooth module receiving Xbox controller input via UART
Flight Control Algorithm

The control loop runs at ~200 Hz and performs the following:

  • Read IMU: Query accelerometer and gyroscope via I2C
  • Attitude Estimation: Fuse sensor data to compute pitch and roll angles
  • Receive Input: Decode throttle, pitch, roll, yaw commands from Bluetooth controller
  • PID Calculation: Three independent PID controllers (pitch, roll, yaw) compute motor corrections
  • Motor Mixing: Convert 4 corrected control signals into individual motor PWM commands using quad mixing matrix
  • Output PWM: Update timer registers with new pulse widths
Challenges & Solutions

Problem: Motors Spinning at Different Speeds

Initially, small differences in ESC calibration or motor characteristics caused the drone to spin during hover attempts. Solution: Implemented a detailed calibration routine that sent identical throttle sequences to each ESC and measured actual motor speed via tachometer feedback, then tuned PWM offsets per motor to achieve perfect synchronization.

Problem: Bluetooth Input Lag

Wireless controller commands arrived at irregular intervals, causing jerky control response. Solution: Implemented a buffered command queue with timeout handling, so the flight loop always had the most recent command without stalling on slow or dropped packets.

Problem: IMU Noise in Attitude Estimation

Raw gyroscope data was noisy over short timescales. Solution: Applied low-pass filtering to gyro output and used complementary filtering to fuse accelerometer data (good for steady-state attitude) with gyroscope (good for dynamic response).

Problem: Battery Voltage Sag During Flight

Supply voltage dropped under high motor current, causing inconsistent throttle response. Solution: Implemented software throttle limiting and motor desaturation to keep ESC input within stable voltage range. Eventually moved to a bench supply for consistent testing.

Testing & Validation

The drone was validated through:

  • Motor Test: Each motor spun individually at full range, verifying no mechanical binding
  • ESC Calibration Check: Throttle input was stepped through full range and motor speed was verified to respond linearly
  • IMU Verification: Pitch/roll angles were logged while physically tilting the drone to verify sensor accuracy
  • PID Tuning: Control gains were iteratively adjusted while running the motor in open-loop, monitoring oscillation behavior
  • Tethered Hover Test: Drone hovered under bench power while physically restrained, allowing safe tuning without crash risk
  • Free Flight Test: With battery power (limited by supply capacity), the drone achieved momentary hover and responded to control inputs
Key Takeaways

This project demonstrated the complexity of real-time embedded systems that must integrate hardware control, sensor fusion, and wireless communication. Precision in ESC calibration and careful PID tuning were essential. The 3-person collaboration also highlighted the importance of clear division of labor — while I focused on flight control, teammates handled power distribution and communication layers, which allowed rapid iteration and debugging.
